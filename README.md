# ISO 27001 & GRC Framework — Public Sector Procurement Readiness (Anonymized Case Study)

> **Note:** This is an anonymized, conceptual version of a university Governance, Risk & Compliance (GRC) group project. The company name, individuals, and municipality have been replaced with fictional placeholders. Internal reference numbers, private document links, and other identifying details have been removed or generalized. It is published here to demonstrate methodology and analytical approach, not to represent any real organization.

## 📌 Project Overview
This repository contains a GRC framework and ISO/IEC 27001:2022 gap analysis developed for **TMC Technology Solutions** (fictional name), a SaaS digital communication platform for elderly care, to help it clear information-security barriers for Swedish municipal procurement (*offentlig upphandling*).

The project bridges technical execution with legal and strategic security requirements, addressing **GDPR**, the **EU NIS2 Directive**, and **ISO/IEC 27001:2022**, using the Swedish Civil Contingencies Agency's (**MSB**) methodology support framework.

This was completed as a group project for an MSc Information Security Management course; this repository reflects my individual contribution and write-up, anonymized for public sharing.

---

## 📂 Repository Contents

### 1. External Analysis (`External-Analysis.xlsx`)
An environmental scanning matrix covering public-sector prerequisites:
* **Stakeholder Mapping:** Municipal Procurement Officers, Data Protection Officers (DPOs), and Digital Inspectors.
* **Legal Frameworks:** Impact assessments for GDPR Article 28 (DPA), Articles 44–46 (third-country data transfers), and Article 35 (DPIA).
* **Macro Trends:** The strategic shift required by the NIS2 Directive's supply-chain security mandates for public entities.

### 2. ISO 27001 Gap Analysis (`Gap-Analysis.xlsx`)
A compliance audit against the ISO/IEC 27001:2022 Annex A controls:
* **Critical Findings (Level 4 – Serious Gaps):** Information Security Policies (5.1), Access Control (5.15), Cloud Services Security (5.23), and Use of Encryption (8.24) — driven by non-EU data hosting risk.
* **Established Baselines:** Solid existing controls for Asset Inventories (5.9) and Information Deletion (8.10).
* **Remediation Mapping:** Connects technical deficiencies to business motivations, forming a roadmap toward procurable status.

### 3. Project Plan (`TMC_Project_Plan_Anonymized.docx`)
The original planning document: problem definition, scope, objectives, deliverables, timeline, resource analysis, and project risk register.

### 4. Project Report (`TMC_Assignment_Report_Anonymized.docx`)
The final write-up: project plan evolution, methodology (Agile + MSB framework), deliverable descriptions, quality-criteria evaluation, and risk management of the project itself.
